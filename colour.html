One number, two readings · Week 5

Linear means proportional: twice the light, twice the number, and 0.5 is half the light. sRGB stores the same light along a curve, with extra precision in the darks, the way our eyes see. So one number in a file can mean two very different amounts of light.

The midpoint surprise

sRGB 0.5 decodes to about 0.214 linear: barely a fifth of the light. Linear 0.5, half the light, is stored as about 0.735 in sRGB.

For a photo that’s right. For a roughness map it’s wrong: every value shrinks, and the surface turns glossy.

The exact sRGB curve (IEC 61966-2-1)

sRGB → linear:
c ≤ 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055)2.4
linear → sRGB:
l ≤ 0.0031308 ? 12.92 l : 1.055 l1/2.4 − 0.055

Not just “gamma 2.2”: near black the curve is a straight line.

Even steps are not even light

Even in the file, read as sRGB · looks even

Even in light, linear · looks bunched up at the bright end

The top row’s middle step is 0.5 in the file but only 21% of the light. The bottom row’s middle step is really half the light, and it looks much brighter. That is why images are stored in sRGB, and why light is calculated in linear.

Averaging black and white

Step back or squint: the lines blend into the middle grey, not the right one. Averaging the sRGB numbers of black and white gives 0.5, the wrong midpoint. (Set your browser zoom to 100% for this one.)

    Where to set it

    Same rule everywhere: colour maps are decoded, data maps are not. Only the name of the switch changes.

    Blender 5.2

    Shader Editor → Image Texture node → Color Space (under the image name)

    MapColor SpaceNotes
    Base colour, emissive coloursRGBThe default for 8-bit images
    Roughness, metallic, AO, height, opacity, packed ORMNon-ColorSet it on every data map, by hand
    Normal mapNon-ColorThen through a Normal Map node into Normal
    HDR sky, EXRLinear Rec.709Blender picks it for float images: leave it
    • The setting is called Non-Color. Blender calculates in Linear Rec.709: sRGB’s primaries and white, without the curve.
    • The view transform (Render Properties → Color Management → View Transform, AgX by default) is for looking at the render. It changes nothing in your maps; never bake it into them.
    • Blender 5.0 rewrote colour management: tutorials from before 5.0 show a different panel.

    Substance 3D Painter

    Fixed per channel · user channels: Texture Set Settings → Color channel · export: File → Export Textures → Output Templates

    ChannelHandlingNotes
    Base color, specular, coat, sheen, scattering colourcolour managedPainter decides; you can’t switch it
    Roughness, metallic, normal, height, AO, opacitydataNever colour managed
    User channelsyour choiceColor channel on for colour, off for data
    Export: Unreal Engine (Packed)ORM in R, G, BAO, roughness, metallic in one file; normals in DirectX. The template for Week 10
    • The project’s colour management (Legacy, OpenColorIO or Adobe ACE) is chosen in the project settings; the export follows it.
    • The storage format (sRGB8, L8, RGB16F …) is not a colour space setting: roughness stays data in any format.
    • Colour maps sRGB, data maps linear. Open the export in a second program before you trust it.

    Unreal Engine 5.8

    Double-click the texture → Details → Texture → sRGB · Compression → Compression Settings

    TexturesRGBCompression SettingsSampler type
    Base colour, emissive colourOnDefault (BC1 or BC3 with A)Color
    Normal mapOffNormalmap (BC5)Normal
    Packed ORM, any maskOffMasks (no sRGB)Masks
    HDR sky, EXROffHDR (RGBA16F, no sRGB)Linear Color
    • The sRGB box is an input decision: how the file was stored. The project’s Working Color Space solves a different problem.
    • Unreal often guesses normal maps right on import, and guessed wrong on our ORM: check every texture after import.
    • Change the sRGB box and the Texture Sample node in the material needs a matching Sampler Type, or the material won’t compile. Unreal sets the sRGB box and compression for .exr and .hdr files on import.
    • A normal map made for Blender is OpenGL; Painter’s Unreal export is DirectX. Mixed up, bumps turn into dents: the texture’s Flip Green Channel fixes it.

    Common gamma failures

    Four failures, one cause: the wrong transform. Fix the setting at its source; never repair it with a colour grade.

    FailureSymptomCauseFix
    Data decoded as colourRoughness, AO or masks shift: 0.5 becomes 0.21, the surface turns glossy, AO too darkA data map read as sRGBNon-Color in Blender; sRGB off for packed masks in Unreal
    Colour decoded twiceToo dark, too saturatedAn already-linear image treated as sRGBAssign the true source space; don’t compensate by eye
    Colour not decodedPale and washed out, low contrastA base colour set to Non-Color, or sRGB offBack to sRGB
    View baked into textureA double look: contrast and tone mapping applied twiceA tone-mapped render reused as if it were scene-linear dataKeep scene data and display output as separate deliverables

    The five-minute check: import one base colour and one roughness map, duplicate each and flip its setting, compare the renders and the numbers, then set them right without adding adjustment nodes.
